# Архитектура системы

## Сбор и хранение

В 1С регламентные задания выполняются по расписанию [@onec-jobs]. В проекте часть показателей рассчитывается заранее. Сборщик в базе публикует последнее сохранённое значение вместе с показателями состояния расчёта. Это позволяет опрашивать базу чаще, чем запускается вычисление, и следить за давностью результата. Для передачи используются числовые метрики в текстовом формате Prometheus с метками для идентификации базы и, где это требуется, задания или направления обмена [@prometheus-exposition].

Отдельный реестр передаёт `vmagent` список целей через HTTP Service Discovery. Новая база может появиться в списке при очередном обновлении реестра. `vmagent` опрашивает цели и отправляет значения в VictoriaMetrics по `remote_write` [@victoriametrics-agent]. У каждого ряда сохраняются метки, по которым панели и правила различают базы.

## Панели и оповещения

Grafana читает показатели из VictoriaMetrics и отображает их на панелях [@grafana-dashboards]. При разборе обращения оператор выбирает нужную базу и интервал времени и сопоставляет показатели доступности и свежести.

`vmalert` выполняет запросы к хранилищу по расписанию и оценивает условия правил. События передаются в Alertmanager, который группирует уведомления и поддерживает подавление связанных оповещений [@victoriametrics-alert; @prometheus-alertmanager]. Так несколько просроченных метрик одной базы могут дать оператору одно уведомление о состоянии сбора.
