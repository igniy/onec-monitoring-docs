# Диагностика сбора метрик

## Интерпретация сигналов

В Grafana выберите нужную базу и сопоставьте состояние опроса, время последнего успешного расчёта и значение прикладной метрики за один интервал. Такая проверка помогает определить, на каком этапе возник сбой.

Table: Интерпретация сочетаний сигналов мониторинга

| Наблюдение | Состояние | Первая проверка |
| :--------------------------------- | :------------------------------- | :------------------------------------- |
| `up = 0` | Опрос цели завершился ошибкой | Состояние цели в `vmagent` и текст ошибки опроса |
| `up = 1`, несколько метрик просрочены | Точка сбора отвечает, сохранённые значения устарели | Общее задание расчёта и последние ошибки в 1С |
| `up = 1`, отметка расчёта отсутствует | Свежесть значения определить нельзя | Включён ли расчёт и был ли успешный запуск |
| `up = 1`, свежая метрика вышла за допустимый порог | Есть актуальный сигнал о сбое прикладного процесса | Обмен, задание или другой объект, указанный в метках |

## Действия оператора

При остановке расчёта откройте историю запусков задания в 1С, проверьте время последнего успешного выполнения и сообщения журнала регистрации. Сопоставьте интервал между запусками с TTL метрики. Если вычисление регулярно завершается позже допустимого возраста, проверьте отдельно расписание задания и длительность расчёта.

Если свежая метрика указывает на отставание обмена, откройте журнал обмена для указанного узла и направления. Для регламентного задания проверьте результат последнего запуска, длительность и соответствие расписанию.

После устранения причины проверьте, что метрика получила новую отметку успешного расчёта. Для предупреждения об отставании сбора дождитесь окончания выдержки восстановления и проверьте его состояние в Alertmanager.
